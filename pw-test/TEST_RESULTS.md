## Ограничения тестов

### 1. Fake Media Devices
Тесты используют флаги Chromium:
```
--use-fake-ui-for-media-stream
--use-fake-device-for-media-stream
```

**Что проверяется:**
- ✅ WebRTC pipeline (захват → кодирование → передача → декодирование → рендеринг)
- ✅ MediaStream треки активны (`live`, `enabled`)
- ✅ `<video>` элементы рендерятся с реальными размерами
- ✅ Статус соединения "Connected"

**Что НЕ проверяется:**
- ❌ Реальное качество звука (слышимость)
- ❌ Реальное качество видео (визуальная проверка)
- ❌ Задержки, эхо, потери пакетов в реальной сети
- ❌ TURN-сервер при NAT

**Для проверки реального звука/видео:** Ручное тестирование на двух устройствах с микрофонами/камерами.

---

### 2. Flutter CanvasKit Rendering
Flutter Web (CanvasKit) рендерит UI на `<canvas>`, поэтому:
- Текст не всегда доступен в DOM
- Файлы, голосовые сообщения могут быть не видны через `getByText()`
- Требуется проверка через скриншоты или aria-labels

**Решение:** Тесты используют комбинацию:
- `getByText()` для семантического дерева
- `locator('[aria-label*="..."]')` для aria-атрибутов
- Скриншоты для визуальной проверки

---

### 3. RTCPeerConnection Stats
`flutter_webrtc` использует нативный binding, поэтому `RTCPeerConnection` не экспонируется в `window`.

**Альтернатива:** Проверка через `MediaStreamTrack`:
- `track.readyState` — состояние трека (`live` / `ended`)
- `track.enabled` — включён ли трек
- `track.muted` — заглушён ли трек
- `track.getSettings()` — параметры (sampleRate, width, height, frameRate)

Это подтверждает что медиа **передаётся**, но не даёт детальной статистики (packetsLost, jitter, RTT).

## Выводы

### ✅ Что работает:
1. **Регистрация и аутентификация** — Supabase Auth (анонимная)
2. **Управление контактами** — добавление, поиск по UUID
3. **Текстовые сообщения** — E2E-шифрование (AES-256-GCM)
4. **Передача файлов** — загрузка, шифрование, доставка
5. **Голосовые сообщения** — запись, загрузка, воспроизведение
6. **Аудиозвонки** — WebRTC, P2P, статус "Connected"
7. **Видеозвонки** — WebRTC, видеотреки, рендеринг `<video>`
8. **История звонков** — сохранение в БД, отображение в профиле

### ⚠️ Ограничения:
1. **Fake media devices** — не проверяют реальное качество звука/видео
2. **Canvas-рендеринг** — файлы/голосовые не всегда видны в DOM
3. **Нет RTC статистики** — `RTCPeerConnection` не доступен в JS (flutter_webrtc native)
4. **Headless download** — скачивание файлов требует user gesture

### 🎯 Рекомендации:
1. **Ручное тестирование** — проверить реальный звук/видео на двух устройствах
2. **Мониторинг RTC** — добавить логирование статистики на стороне Flutter (через flutter_webrtc API)
3. **Accessibility** — улучшить семантическую разметку для файлов/голосовых (aria-labels)
4. **E2E на реальных устройствах** — Android + Web, проверка TURN-сервера при NAT
