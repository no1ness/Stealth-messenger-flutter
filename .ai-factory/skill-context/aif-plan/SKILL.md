### Verify Apple Liquid widget existence before referencing
**Source**: tech-fact discovered during `/aif-improve` Pass 3 (feature/diagnostics-logs-screen)
**Rule**: Before naming a widget from `client/lib/themes/apple_liquid/` in a plan task, confirm it actually exists. The directory ships `GlassContainer`, `GlassButton`, `GlassCard` (in `components/glass_container.dart`) and `GlassAppBar` (in `widgets/glass_app_bar.dart`). `GlassPageRoute` and `GlassListTile` do NOT exist — for navigation use `MaterialPageRoute` (matches the existing pattern at `settings_screen.dart:386`). `GlassButton` takes `child: Widget`, not `icon`/`label` — wrap icon+text in a `Row` inside `child`.

### Verify Logger signature
**Source**: tech-fact, `client/lib/logging/logger.dart:110`
**Rule**: The exact public signature is `Logger.{debug,info,warn,error}(String message, {Map<String,dynamic>? extras})`. There is NO `tag` parameter — by convention tags are written as a bracket prefix in the message (e.g. `Logger.debug('[diag.ui] filter changed', extras: {'level': level.name})`). Plans that show `Logger.debug('tag', 'message')` are wrong and will not compile.

### Map service lifecycles before integrating
**Source**: tech-fact (audit during `/aif-improve`) + patch 2026-04-30 ("Keep signaling dependencies isolated behind dedicated services")
**Rule**: Before designing a task that holds a reference to one of these services, map its lifecycle. `WebRtcSignalingService` is created **per call** in `native_call_controller.dart`, `web_call_controller.dart`, and `p2p_service.dart` (no stable singleton). `P2PService.instance` IS a singleton. `LocalAppService` is created per widget-state (`settings_screen.dart:24`), NOT a singleton, and has no `dispose()` — services owned by it that hold timers/streams MUST be ownership-transferred to the consuming screen via a factory method, or they leak on every open/close.

### Provider-closure DI for testable aggregators
**Source**: tech-fact (audit during `/aif-improve` Pass 4)
**Rule**: This project's sub-services (`DashboardService`, `AttachmentService`, `IdentityService`) have parameterless constructors and create their own internal dependencies (`_localDb`, `_storage`) — they cannot be substituted in unit tests without rewriting them all. When planning a new service that aggregates existing ones, its constructor MUST accept **provider closures** (`Future<X> Function()` / `T Function()`) instead of the concrete service types. In production, pass method tear-offs (`_dashboard.getDashboardSummary`); in tests, pass fake closures. The same applies to UI widgets that depend on global statics like `Logger.snapshot` — accept an injectable `logProvider` parameter with the static as default.

### Reject new cloud-backend proposals
**Source**: patch 2026-05-12 + `.ai-factory/rules/base.md`
**Rule**: This project is local-first and explicitly forbids new external backends for contacts, message history, attachments, and call history. Any plan that introduces a cloud sync layer, history-backup service, or non-PocketBase-signaling external service MUST stop and flag to the owner before writing tasks. PocketBase is allowed ONLY as transient WebRTC signaling.
