### Verify service API before generating code
**Source**: tech-fact, `client/lib/services/dashboard/dashboard_service.dart:36-37`, `client/lib/services/attachments/attachment_service.dart:371-372`
**Rule**: Several existing services return hardcoded values that **look like** health signals but aren't. `DashboardService.getDashboardSummary()` returns `bucketReady: true` and `localMediaReady: true` as compile-time constants — only `secureStorageReady` reflects real state. `AttachmentService.getStorageDebugSummary()` is similar — only `fileCount` is real. ### dotenv direct read for graceful degradation
**Source**: tech-fact, `client/lib/services/signaling/pocketbase_client.dart:30`
**Rule**: `PocketBaseClient.instance` throws `StateError` when `POCKETBASE_URL` is unset or empty. Code paths that should degrade gracefully on missing config (health checks, env-info collectors, diagnostics) MUST read `dotenv.env['POCKETBASE_URL']?.trim()` directly and handle null/empty themselves — never call `PocketBaseClient.instance` unconditionally in those paths.

### Test-safe widget constructors
**Source**: patch 2026-04-30 ("Widget constructors should not require global env initialization")
**Rule**: A widget's `const` constructor and its `State.initState()` MUST NOT depend on `dotenv.env`, `flutter_dotenv` load state, or any other global runtime bootstrap. All env-dependent values are resolved in `main.dart` and passed in (via constructor or a top-level service like `LocalAppService`). Widget tests must be able to `pumpWidget` the screen without calling `dotenv.load()` first.

### share_plus on web path
**Source**: tech-fact, package_info_plus 8.x + share_plus 10.x docs
**Rule**: `path_provider.getTemporaryDirectory()` is not available on web, and `Share.shareXFiles` depends on a temp file path. ### Inline scrubber for any exported log text
**Source**: tech-fact (security finding during `/aif-improve` Pass 1)
**Rule**: `Logger`'s auto-redaction in `lib/logging/logger.dart` only redacts **values in the `extras` map** under keys in `_sensitiveKeys`. Identifiers (UUID v4, 15-char PocketBase ids, base64 ed25519 pubkeys) interpolated **inline** into the message body — e.g. `Logger.warn('chat $userId failed')` — bypass that guarantee. Any code that exports raw log text outside the device (share intents, file dumps, upload to a remote sink, clipboard for support) MUST pass every line through `scrubInlineSensitive` from `client/lib/services/diagnostics/log_scrubber.dart` before writing it out. The function is idempotent — safe to call multiple times.
