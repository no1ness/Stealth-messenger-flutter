# PB 0.23 unit test expectations for 15-char id truncation

**Date:** 2026-06-12 16:30
**Files:** 
- `client/test/services/signaling/pb_user_id_test.dart`
- `client/test/services/signaling/rtc_message_test.dart`
**Severity:** low

## Problem

7 unit tests failed after `pbIdFromLocalUuid` was changed to truncate IDs to 15 characters for PocketBase 0.23 compatibility. Tests expected full 32-char hex or original-length strings, causing assertion failures.

## Root Cause

When PocketBase was upgraded from 0.22 to 0.23, the `id` field max length dropped from 32 to 15. The `pbIdFromLocalUuid` function was correctly updated to truncate, but the corresponding tests (`pb_user_id_test.dart`, `rtc_message_test.dart`) were not updated to reflect the new behavior. This is a test-accuracy gap — the production code was correct, the tests were stale.

## Solution

Updated test expectations in both files:

1. **`pb_user_id_test.dart`** — All 6 `pbIdFromLocalUuid` expectations changed from 32-char hex to first-15-char truncated form. Round-trip tests updated to reflect that UUID→PB→UUID is no longer reversible (15-char truncation loses information). Test names updated to accurately describe truncation behavior.

2. **`rtc_message_test.dart`** — `pbId` constant changed from 32-char to 15-char truncated form. The "fromRecord rehydrates pb-id back into canonical UUID form" test updated to expect the truncated 15-char pbId passed through unchanged, since `localUuidFromPbId` only reconstructs UUIDs from 32-char hex strings.

## Prevention

- When modifying `pbIdFromLocalUuid` or any ID transformation function, update both the function and its tests simultaneously
- After PocketBase version bumps, run all signaling tests (`flutter test test/services/signaling/`) to catch schema-contract mismatches
- The round-trip asymmetry (UUID→pbId is lossy) is now documented in test names; any future change to truncation length must update these tests
