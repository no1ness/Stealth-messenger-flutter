# Remove accidental direct `crypto` dependency

**Date:** 2026-06-11 14:00
**Files:** `client/pubspec.yaml`
**Severity:** low

## Problem

`client/pubspec.yaml` contained `crypto: ^3.0.7` as an unintended direct dependency. This was auto-promoted from transitive during `flutter pub get` while implementing the one-button app updates feature. The codebase uses the `cryptography` package for crypto operations, not `crypto`.

## Root Cause

During iterative `flutter pub get` runs while adding new packages (package_info_plus, path_provider), the Flutter tool resolved `crypto` (a transitive dep of `cryptography` or another package) and promoted it to `dependency: "direct main"` in pubspec.lock. The developer did not notice this promotion because `flutter pub add` was not used — manual edits to pubspec.yaml followed by `flutter pub get` can trigger automatic dependency resolution changes.

There was no regression gate or CI step that flags newly introduced direct dependencies that were not explicitly added by the developer.

## Solution

Removed `crypto: ^3.0.7` line from `client/pubspec.yaml`. The next `flutter pub get` will demote it back to `dependency: transitive` in `pubspec.lock`. No code changes needed — no imports of `crypto` were added during the update feature.

## Prevention

- After any `flutter pub get`, diff `pubspec.lock` and review new `dependency: "direct main"` entries
- Consider a CI step that compares direct dependencies against a known-good baseline
- Use `flutter pub add <package>` instead of manual pubspec.yaml edits + `flutter pub get` when adding intentional dependencies
