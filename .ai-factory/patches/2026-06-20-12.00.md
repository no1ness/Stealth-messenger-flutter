# Caddy TLS configuration for web app on fallback port

**Date:** 2026-06-20 12:00
**Files:** server/docker/scripts/ensure-web-cert.sh, server/docker/scripts/deploy-web.sh, server/docker/scripts/deploy-native.sh, server/docker/scripts/deploy-bypass.sh, server/docker/.env.example, .ai-factory/plans/feature-web-global-deploy.md
**Severity:** medium

## Problem

`https://app.stealthpro.ru` → `ERR_CONNECTION_REFUSED`. 
- Port 80: not configured in Caddy (native mode)
- Port 443: occupied by sing-box (VLESS-Reality, masquerading as telemost-ios.yandex.ru)
- Port 8445: Caddy served web app in plain HTTP, no TLS

Users couldn't access the web app through a standard HTTPS URL.

## Root Cause

Sing-box was deployed before the web app was ready, occupying port 443. When the web deploy scripts were created (`deploy-web.sh`, `deploy-native.sh`), they used fallback ports (8445) but never configured TLS because Caddy's automatic HTTPS requires port 80 for HTTP-01 challenge, which wasn't available in native mode.

The `deploy-native.sh` already installed `certbot` (for coturn certs) but never used it to obtain web domain certificates.

## Solution

1. Created `ensure-web-cert.sh` — a certbot wrapper using DNS-01 challenge (Cloudflare API token) to obtain/renew Let's Encrypt certificates without needing port 80
2. Added `DNS_API_TOKEN` variable to `server/docker/.env.example`
3. Updated all three deploy scripts (`deploy-web.sh`, `deploy-native.sh`, `deploy-bypass.sh`) to call `ensure-web-cert.sh` and add `tls` directive to the Caddy web block pointing to the obtained certificate
4. When `DNS_API_TOKEN` is not set, scripts degrade gracefully (no TLS, warning message)
5. Updated verification in `deploy-web.sh` to use HTTPS scheme when TLS is active
6. Updated documentation references from `https://app.stealthpro.ru` to `https://app.stealthpro.ru:8445`

## Prevention

- When adding a new public-facing service behind sing-box (which owns port 443), always handle TLS explicitly:
  - Either use DNS-01 challenge (needs DNS provider API token) 
  - Or set up SNI-based routing (HAProxy on port 443)
  - Or document the non-standard port prominently
- Deploy scripts should always check if TLS dependencies are configured before assuming automatic HTTPS
- `.env.example` should list all required API tokens upfront
