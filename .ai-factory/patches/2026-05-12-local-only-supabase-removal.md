# Patch: Remove Legacy Cloud Backend From Contacts And History

## Context

The project direction changed to local-first only for contacts, message history, attachments, and call history. Network services are limited to WebRTC/P2P transport and PocketBase transient signaling.

## Changes

- Replaced the old app service facade with `LocalAppService`.
- Removed cloud history/contact service files, background sync service, SQL migrations, and cloud diagnostic tools.
- Removed direct backend dependencies from `pubspec.yaml` and lockfile.
- Reworked startup/env docs around `POCKETBASE_URL` only.
- Changed contact add flow to require contact bundles containing public keys.
- Updated WebRTC DataChannel signaling to use PocketBase messages marked with `purpose=datachannel`.
- Updated project docs, AI Factory context, and E2E labels away from cloud-history assumptions.

## Lessons

- Local-first contact add cannot accept raw user IDs because E2E requires the peer public key.
- Historical plan/docs can reintroduce wrong architecture; active AI context must be updated with code changes.
- If Flutter SDK is unavailable in PATH, `pubspec.lock` cannot be regenerated by tooling and must be verified later with `flutter pub get`.
