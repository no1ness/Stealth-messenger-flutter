# 🔹 Техническое задание: Stealth Messenger

## Задача
Создать безопасный, лёгкий и быстрый кроссплатформенный мессенджер для небольшой общины (до нескольких тысяч пользователей).
Основная цель — максимальная приватность, минимум данных на сервере, сквозное шифрование, удобство и скорость, отсутствие блокировок (или их минимизация).

## 🔸 Общие требования
- 📱 **Кроссплатформа**: Android + Web (через Flutter).
- ⚙️ **Серверная часть**: Supabase (PostgreSQL + Realtime + Storage) — используется **только как резервное хранилище**:
  - синхронизация сообщений при наличии сети;
  - хранение публичных ключей и минимальных метаданных;
  - сигналинг WebRTC-звонков (Broadcast);
  - **Без** хранения личных данных, паролей, открытых контактов.
- 🛠️ **Архитектура**: **Local-First** — сообщения хранятся на устройстве в зашифрованной LocalDB, Supabase — backup. P2P-компоненты через WebRTC (звонки и DataChannel).
- ☁️ **Хостинг**: Supabase (вне юрисдикции нежелательных регионов).
- 🔄 **Резерв**: Все сообщения и чаты дублируются в зашифрованном `LocalDatabaseService` (idb_shim + AES-256-GCM). При offline — работа без сервера.
- 🔐 **Шифрование**: End-to-end (X25519 + AES-256-GCM + Double Ratchet) с локальными ключами на устройстве. Локальная БД также шифруется.
- ⚡ **Производительность**: Мгновенная доставка сообщений, локальное кэширование, отзывчивый интерфейс.

## 🔸 Функционал

### 1. Авторизация
- Без телефона, email и пароля (Anonymous Auth).
- При первом запуске локально генерируется уникальный `user_id` (UUID v4) и пара ключей (публичный/приватный).
- Пользователь соглашается с правилами.
- Можно экспортировать/импортировать ключ для восстановления сессии.
- Возможность задать псевдоним/ник (необязательно).

### 2. Контакты
- Добавление по ID.
- Список контактов хранится локально (связка `user_id` -> `contact_user_id`).
- Сервер хранит только публичные ключи для старта E2E-общения.

### 3. Чаты
- Индивидуальные (и в будущем групповые).
- Сообщения шифруются локально на клиенте и синхронизируются через Supabase.
- Поддержка:
  - текстовых сообщений;
  - изображений / аудио / файлов (сохраняются в Supabase Storage в зашифрованном виде).

### 4. Аудио- и видеозвонки
- Реализованы через WebRTC с прямым P2P-медиа (голос и, при выборе пользователя, видео).
- Старт с экрана **Контакты**: голосовой или видеозвонок; в сигнализации указывается тип (`call_type`: `audio` / `video`).
- Обмен SDP/ICE через Supabase Broadcast (сигнальный сервер); медиа не проходит через Supabase.
- Без записи и хранения содержимого звонков на сервере (в истории возможны только метаданные статуса/длительности).
- Для прохождения NAT рекомендуется настроить TURN в `client/.env` (`TURN_URL`, `TURN_USERNAME`, `TURN_PASSWORD`).

### 5. Безопасность и приватность
- Строгое End-to-end шифрование сообщений.
- Приватный ключ никогда не покидает устройство (в Web хранится локально, на Android — во встроенном Keystore).
- Включен Row Level Security (RLS) и Rate Limiting на сервере.
- Все логи и кэши — только локально (по желанию очищаются).

### 6. Интерфейс
- Дизайн-система: **Apple Liquid (Glassmorphism)**, минимализм, плавность.
- Главные экраны:
  - Список чатов
  - Контакты
  - Настройки
  - Профиль (ID, экспорт ключа)

## 🔸 Структура Supabase (Актуальная)

### Таблица `users`
| Поле | Тип | Описание |
|---|---|---|
| `id` | `uuid` (PK) | Уникальный идентификатор |
| `nickname` | `text` | Необязательный ник |
| `public_key` | `text` | Публичный ключ X25519 |
| `created_at` | `timestamp` | Дата регистрации |

### Таблица `chats` & `chat_members`
| Поле | Тип | Описание |
|---|---|---|
| `id` | `uuid` (PK) | ID чата |
| `is_private`| `boolean`| Тип чата (приватный/групповой) |
| `user_id` | `uuid` (FK)| (в `chat_members`) Участник чата |

### Таблица `messages`
| Поле | Тип | Описание |
|---|---|---|
| `id` | `uuid` (PK) | ID сообщения |
| `chat_id` | `uuid` (FK) | Привязка к чату |
| `sender_id`| `uuid` | Отправитель |
| `content` | `text` | **Зашифрованное** сообщение (Base64) |
| `message_type`| `text` | Тип (text, image, audio) |
| `created_at`| `timestamp` | Время отправки |

### Хранилище (Storage)
- Шифрованные медиафайлы (картинки, аудио). Файлы шифруются на клиенте до загрузки.

## 🔸 Дополнительно
- 🚫 **Без рекламы, трекинга, аналитики.**
- 💬 **Пуш-уведомления** / реалтайм обновления через Supabase Realtime & Broadcast.
- ⚙️ **Офлайн-режим**: полноценная работа без сервера. Сообщения сохраняются локально (зашифрованы AES-256-GCM). При восстановлении сети `SyncService` автоматически отправляет накопленные сообщения в Supabase (upsert, идемпотентно).
- 📦 **Резервное копирование** ключей (вручную пользователем).
