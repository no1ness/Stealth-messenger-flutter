🔹 Техническое задание для ИИ-агента

Задача: Создать безопасный, лёгкий и быстрый кроссплатформенный мессенджер для небольшой общины (до нескольких тысяч пользователей).
Основная цель — максимальная приватность, минимум данных на сервере, сквозное шифрование, удобство и скорость, отсутствие блокировок (или их минимизация).

🔸 Общие требования

📱 Кроссплатформа: Android + iOS (через Flutter).

⚙️ Серверная часть: Supabase (PostgreSQL + Auth + Storage) — только для:

хранения минимальных данных (ID, публичный ключ, список чатов);

синхронизации сообщений и пушей;

без хранения личных данных, паролей, контактов.

🛠️ Архитектура: client-centric + P2P-компоненты через WebRTC (для звонков и прямой передачи сообщений).

☁️ Хостинг: Supabase на VPS за пределами РФ (например, Европа).

🔄 Резерв: дублирование данных в зашифрованном виде у клиента.

🔐 Шифрование: end-to-end с локальными ключами (на клиенте, не на сервере).

⚡ Производительность: мгновенные доставки сообщений и звонков, локальное кэширование.

🔸 Функционал
1. Авторизация

Без телефона, email и пароля.

При первом запуске генерируется уникальный user_id и пара ключей (публичный/приватный).

Пользователь соглашается с правилами (чекбокс).

Можно экспортировать/импортировать ключ для восстановления.

Возможность добавить псевдоним/ник, не обязательный.

2. Контакты

Добавление по ID или QR-коду.

Список контактов хранится локально.

Сервер лишь хранит пары публичных ключей для начала общения.

3. Чаты

Индивидуальные и групповые.

Сообщения шифруются локально и синхронизируются через Supabase.

Приоритет: локальная доставка и P2P, Supabase — только для офлайн-синхронизации.

Поддержка:

текстовых сообщений,

изображений,

аудио (голосовые),

файлов (в Supabase Storage в зашифрованном виде).

4. Голосовые и видеозвонки

Реализовать через WebRTC с прямым соединением.

Обмен SDP через Supabase Realtime или короткоживущие сигнальные серверы.

Приоритет P2P, при недоступности — fallback через TURN/STUN.

Без записи и хранения данных.

5. Безопасность и приватность

End-to-end шифрование всех сообщений и звонков.

Приватный ключ — только на устройстве.

Минимум данных на сервере: ID, публичный ключ, список активных чатов.

Все логи и кэши — только локально и по желанию очищаются.

6. Интерфейс

Минимализм, скорость, удобство.

Flutter UI с использованием Material 3.

Главные экраны:

Список чатов

Контакты

Настройки

Профиль (ID, QR-код, экспорт ключа)

🔸 Дополнительно
